# 主張A（補題9.7）の修正 — 紙の式は**両方向に**外れる

*2026-08-22 夜間 autoresearch。* 対象は `research/09-two-point-lower-bound.md`
の補題9.7（主張A）。**定理9.6 の証明は無傷**（理由は §4）。

## 1. これまでの記録と、その誤り

紙の主張Aは、新鮮応答状態（0 から `k₀` 辺、1 から `k₁` 辺、`r` 本の
迷いパス `j₁ … j_r` 辺）について、別軌道完成の存在を

```
∃ m | ℓ :  max(k₁+1, q+r+2−ℓ) ≤ m ≤ N−ℓ                    … (旧式)
```

と特徴づける（`q = k₀+k₁+Σjᵢ`）。前夜までに機械検査で分かっていたのは

* 下界領域 `q < min(ℓ−2, k₁*)` の **70 状態では旧式は正しい**、
* 領域外に **8 件の反例**があり、すべて「旧式 = True・真 = False」、

の 2 点だった。この 8 件から `NIGHTLOG.md` は
**「式は過大評価する側にのみ外れ、過小評価は 1 件も無い」**と結論していた。

**この結論は誤りである。** 掃引範囲が `N ≤ 10` に閉じていたためで、
`N = 11` に伸ばすと**逆向きの反例**が出る（§3）。過小評価は下界の証明を
壊しうる向きなので、区別して記録しておく価値がある。

## 2. 修正版の判定条件

誤りの根は `q+r+2−ℓ` という**頂点の総数勘定**にある。これは二重に粗い。

1. **迷いパスはアトミック**。`j` 辺の迷いパスは `j+1` 頂点の塊で、
   どれか 1 つのサイクルが丸ごと飲み込むしかない。総数勘定は塊を
   割ってよいことにしてしまう（→ 過大評価、8 件）。
2. **0 の軌道の外の開示頂点が 1 の軌道に入るとは限らない**。
   第三のサイクル（長さは ℓ の約数なら何でもよい）に入ってよい。
   `q+r+2−ℓ ≤ m` はこれを禁じてしまう（→ 過小評価、§3）。

両方を直すと、判定は算術式ではなく**詰め込み可能性**になる:

> **修正版（`PackSide`）.** 次を満たす `m` と割り当てが存在する:
>
> * `m | ℓ`, `k₁+1 ≤ m ≤ N−ℓ`（1 の軌道長）、`k₀+1 ≤ ℓ`
> * 迷いパスの塊（サイズ `sᵢ = jᵢ+1`）を
>   **0 の軌道 / 1 の軌道 / 任意本数の第三サイクル**へ割り当てる。
>   第三サイクルの長さは `ℓ` の約数で、その群の合計以上。
> * 各サイクルの詰め物（未開示点）の総数が
>   `U = N − (q+r+2)` 以内。
>
> 余った未開示点は不動点にしてよい（`1 | ℓ`）。

**実装と検査**（`research/claimA_fixed.py`）:

| 検査 | 範囲 | 結果 |
|---|---|---|
| 修正版 vs 全数 brute | ℓ ≤ 7, N ≤ 11, **830 状態** | **不一致 0** |
| 修正版 vs 独立第二実装 `--cross` | ℓ ≤ 8, N ≤ 14, **1954 状態** | **不一致 0** |

第二実装 `fixed_greedy` はアルゴリズムが違う（部分集合の再帰的群分け
ではなく、塊への**ラベル付け全数 + 最小約数への丸め**）。Lean 側は
この第二の書き方を写している。

## 3. 九件目の反例 — 旧式の**過小評価**（新規）

```
N = 11, ℓ = 6, k₀ = 0, k₁ = 0, strays = [1,1,1,1]
```

開示頂点は `q+r+2 = 4+4+2 = 10`、未開示は 1 点。

* **旧式**: `max(k₁+1, q+r+2−ℓ) = max(1, 4) = 4`、`N−ℓ = 5`。
  6 の約数は `1,2,3,6` で `[4,5]` に無い → **False**（存在しないと言う）。
* **真**: 存在する。証人

  ```
  (0 2 3 4 5 10)   (1)   (6 7)   (8 9)          6 + 1 + 2 + 2 = 11
  ```

  0 の軌道は長さ 6 = ℓ（迷いパス 2 本と余りの 1 点を飲む）、
  **1 は不動点**（`m = 1`）、残る迷いパス 2 本は 2-サイクル（`2 | 6`）。
* **修正版**: True。

`m = 1` で足りるのに旧式が `m ≥ 4` を要求していた、というのが誤りの姿。
第三サイクルの存在を勘定に入れていない。

**Lean での確定**（`FiniteOrderTM/TwoPointClaimAPackCert.lean`）:
`formula_undercounts` が `¬FormulaSide ∧ CompletionSide ∧ PackSide` を与える。
`CompletionSide` は証人 1 本の検査で足りる（否定される主張が**非存在**
主張なので、全数列挙 `11! = 39916800` は不要）。

## 4. 定理9.6 への影響 — **無い**

九件目は **領域外**である: `k₁*(11,6) = 3` なので
`min(ℓ−2, k₁*) = min(4,3) = 3` に対し `q = 4`。

定理9.6 の下界が消費するのは主張Aの**領域内**の向きだけで、そこは
`TwoPointClaimAGeneral.lean` が一般証明を与えている（`native_decide`
不使用）。掃引した 101 の領域内状態すべてで旧式・修正版・brute の三者が
一致する（過小評価は領域内に 1 件も無い）。**定理9.6 は上下とも無傷。**

## 5. 紙への提案

補題9.7 の記述を次のように分けること。

1. **下界が使う形**（現状のまま正しい）: 「領域内では、別軌道完成が
   存在する ⟺ 旧式」。適用範囲を `q < min(ℓ−2, k₁*)` と明記する。
2. **一般の形**（旧式を撤回し、修正版に差し替える）: 旧式は必要条件でも
   十分条件でもない。反例は両向きに存在する（8 件 + 1 件、§1・§3）。
   一般の特徴づけが要るなら §2 の詰め込み条件を書く。
3. 現状の紙は 1 と 2 を区別せずに旧式を無条件の同値として述べている。
   **そこが直すべき箇所。**
