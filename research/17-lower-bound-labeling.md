# 下界の木帰納で見つかった設計上の問題 — 頂点番号が状態成長で動く

2026-08-10、ループ autoresearch #42。定理9.6 の下界を木の帰納で閉じる
最後の段で、**新鮮応答戦略を具体的に定義できない**ことが分かった。
原因と、取るべき修正の方針を残す。

## 何が問題か

`AdvState.edges`（`TwoPointClaimA.lean`）の埋め込みは頂点番号を
**グループ順**に割り当てている:

```
0 / 1 / P₀ の新頂点 [2, 2+k₀) / P₁ の新頂点 [2+k₀, 2+k₀+k₁) /
迷い頂点 [2+k₀+k₁, vc) / 未開示 [vc, N)
```

P₁ の開始番号が `2 + k₀` なので、**P₀ を 1 歩伸ばすと（k₀ += 1）
P₁ と迷い頂点の番号がすべて 1 ずつずれる**。

決定木の各ノードは具体的な点 `x : Fin N` を問う。敵対者はその場で
答えを返さねばならないが、返した頂点の「番号」は後続の手で P₀ が
伸びると変わってしまう。つまり `Strategy.answer : AdvState → Fin N → Fin N`
を、この埋め込みと整合するように定義できない。

（`play` / `play_q_le` / `play_inLowerRegion` / `runs_iff_goodOutput_playLeaf`
などの**予算勘定と一致補題は戦略に依らず成立している**ので、そこは無傷。
足りないのは「具体的な戦略が存在し、その答えが完成と一致する」ことだけ。）

## 修正の方針（推奨: 付け替え（relabeling）の輸送）

グループ順の埋め込みは**存在証明のための1つの標識付け**にすぎない。
「完成が存在する」という性質は頂点の付け替えで不変なので、
次の補題を足すのが最小の修正になる:

> `τ : Perm (Fin N)` を「具体的な対局で現れた標識」→「グループ順の標識」
> の付け替えとする。`f` がグループ順状態の完成なら、`τ⁻¹ * f * τ` は
> 具体状態の完成であり、`GoodOutput` も `τ` で輸送される。

これがあれば、主張Aで得た完成（`sameCyclePerm` / 別軌道完成）を
そのまま具体的な対局の状態へ移せる。木の帰納は戦略を
**allocation 順（開示された順）で番号を振るもの**として定義すればよく、
状態の成長で番号が動かなくなる。

### 代案（採らない）

`AdvState` を allocation 順の埋め込みに作り直す案もあるが、
`cycle0Verts` / `sameCycleVerts` / `strayBlocks` などの構成と
それらの Nodup・隣接補題（合計 1000 行超）がグループ順の区間
（`List.range'`）に強く依存しているため、書き直しの費用が大きい。
付け替えの輸送なら**既存の証明を一切触らずに済む**。

## 次にやること

1. 付け替えの輸送補題（`IsCompletion` と `GoodOutput` の共役不変性）
2. allocation 順の具体戦略 `freshStrategy : Strategy N` の定義
3. 「その戦略の答えは、付け替え後の完成と一致する」（`Agrees`）
4. 既証明の撃墜（4型）と `not_winsAt_of_bad_leaf` を合わせて下界を閉じる

**この節の内容は否定的結果だが、素朴な道が塞がっていることの確認**であり、
次のセッションが同じ壁に時間を使わないための記録である。
