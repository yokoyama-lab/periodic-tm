## 発見1: (⇒) は完成の存在を使わない（紙より短い道）

紙の (⇒) は「任意の完成の 1 の軌道長 m」を経由していたが、領域条件
`q < k₁*` 自体が `¬Kills` ＝ **窓 [q+1, N−ℓ] に ℓ の約数 m が存在**を
与え、`m ≥ q+1 ≥ max(k₁+1, q+r+2−ℓ)`（`k₁ ≤ q`・`r ≤ q ≤ ℓ−3`）。
よって **領域内では式側は無条件に真**（`inRegion_formulaSide`、Lean 済）。
系として主張Aの iff は「領域内では両側とも真」に簡約される — 有界検証で
全70状態が「両側成立」だったことの説明でもある。

軌道長経由で証明した `orbit1_dvd_and_le`・`k1_succ_le_orbit1` は

## 残る本丸: (⇐) = 領域内で完成を構成する（inRegion_completionSide）

目標: `Fits ∧ InLowerRegion → CompletionSide`。窓の約数 m（¬Kills の
証人、m ≥ q+1）を取り、
- 0 のサイクル（長さ ℓ）: `0 :: P₀新頂点 :: 迷いパス（一部）:: 未開示点で充填`
- 1 のサイクル（長さ m）: `1 :: P₁新頂点 :: 迷いパス（残り）:: 未開示点で充填`
- 残りの点はすべて固定点（1 ∣ ℓ なので位数条件 OK）

### 頂点勘定（大域）は足りている

未開示点数 U = N − vertexCount。2 サイクルの充填需要
= (ℓ + m) − (置いたパス頂点数) 。`m ≤ N − ℓ` より ℓ + m ≤ N なので
需要 ≤ U ✓（大域の勘定は窓の上端で保証される）。

### ⚠ 未解決の crux: 迷いパスの 2 ビン割当（アトミック性）

各迷いパス（jᵢ+1 頂点）は**丸ごと**どちらかのサイクルに入る。
ビン容量: c₀ = ℓ − 1 − k₀、c₁ = m − 1 − k₁（頂点数ベース）。
大域勘定 V₀ ≤ c₀ + c₁ だけでは 2 ビン詰めは一般に不可能
（例: c₀ = c₁ = 3, アイテム {2,2,2}）。**領域外の反例8件はまさに
この型**なので、領域条件がどこで効くかを正確に見極める必要がある。

候補となる追加の腕力:
1. **m を大きく取り直す**: 窓には m だけでなく、より大きい約数
   （最大 D_max = N−ℓ 以下の最大約数）も入りうる。c₁ を最大化して
   「全迷いパスを 1 側に入れる」割当が可能かを先に検討する。
   全部 1 側: V₀ ≤ c₁ ⟺ Σjᵢ + r ≤ m − 1 − k₁。m ≥ q+1 なら
   m − 1 − k₁ ≥ q − k₁ = k₀ + Σjᵢ なので **k₀ ≥ r なら成立**。
2. k₀ < r の場合: 迷いパスは r 本、各 ≥ 2 頂点。0 側の容量
   c₀ = ℓ−1−k₀ は Σjᵢ ≤ ℓ−2−k₀−k₁ より Σjᵢ + 1 ≤ c₀ − k₁ + 1 …
   **1 本を 0 側に移すだけで足りるか**（最大アイテムを 0 側へ、残りを
   1 側へ、の 2 分割で常に足りるかの算術）を先に有限検査で確かめる:
   python で「領域内全状態 × 窓の全約数」について 2 分割可能性を全数
   検査し、常に『最大を 0 側・残りを 1 側』で足りるなら、その形だけを
   Lean 化すればよい（構成は決定的になり場合分けが 1 段で済む）。
3. だめなら一般の 2 ビン詰め補題（First-Fit-Decreasing の保証）が必要。
   これは重いので 1–2 の算術で閉じることを強く優先する。

### 構成の Lean 実装形

割当が決まれば構成は `ofCycles`（Cert で証明済みの道具）と同型:
サイクルをリテラルでなく `List` の結合として書き、
- `f ^ ℓ = 1`: 各サイクル長（ℓ と m ∣ ℓ）が ℓ を割ること
- 軌道長 = サイクル長・辺の拡張・0/1 別軌道
を formPerm の一般補題（`List.formPerm_apply_*`, mathlib）で示す。
有限インスタンスで native_decide 検査済みの `ofCycles` と同じ経路なので、
検証の道具立ては流用できる。
